Настройка рабочего места

Часть 3. «Демо Банк» - сквозной проект №1. Первая глава: собираем на своей Windows 11 то окружение, в котором дальше будет жить весь проект.

Короткий переход. До этого момента в книге был один настоящий проект - роутер: покупка, домашняя сеть, развилка про свой сервер. Дальше начинается второй проект, параллельный первому. Он вымышленный, но подаётся всерьёз, как рабочая задача: небольшой банк под названием Демо Банк - у него есть сайт, база данных, сотрудники и требование "чтобы работало". На Демо Банке мы по очереди пройдём весь набор инструментов профессии DevOps с нуля: git, Docker, сборка, автоматический выпуск обновлений, мониторинг. Через несколько десятков глав мы вернёмся к настоящему роутеру - но уже с этими инструментами в руках, и он перестанет быть "коробкой с наклейкой".
Честная оговорка на всю главу. Установка программ - самая быстро устаревающая часть любого курса: меняются версии, названия кнопок в мастере установки, порядок галочек. Поэтому здесь нет скриншотов установщиков и нет "актуальных" номеров версий - вместо этого объясняется, что мы ставим, зачем это нужно и как проверить, что установилось. Проверка командой - единственное, что не устаревает. Все версии в примерах ниже записаны условно, в виде x.y.z, чтобы не выдавать выдуманные числа за настоящие.

Зачем на Windows нужен Linux: WSL2

Теория. Windows прекрасно работает сам по себе - вопрос не в этом. Вопрос в том, что почти все серверы в мире работают на Linux (другая операционная система, бесплатная и исторически "серверная"), и все инструменты профессии - Docker, скрипты для автоматизации, серверные программы - написаны в первую очередь под Linux. WSL2 (Windows Subsystem for Linux, "подсистема Windows для Linux", версия 2) - это официальная часть Windows 11, которая запускает внутри Windows настоящее ядро Linux. Не имитацию и не "похожие команды", а реальный Linux, который живёт рядом с Windows и которому можно дать те же команды, что и настоящему серверу. Ты остаёшься в своей системе, но получаешь настоящий линуксовый терминал.

Пример. Дальше в проекте Демо Банк мы напишем файл-инструкцию для Docker и запустим её командой. На арендованном сервере эта команда выглядит ровно так же, как в WSL2 на твоём ноутбуке. Это и есть смысл WSL2: то, что заработало у тебя дома, повторяется на сервере без переписывания под другую систему.
Проверь себя. Чем WSL2 отличается от "программы, которая делает вид, что она Linux"?
ОтветВнутри WSL2 работает настоящее ядро Linux, поэтому линуксовые программы (включая Docker) выполняются по-настоящему, а не переводятся на язык Windows. Поведение почти такое же, как на настоящем сервере.

Практика: установка WSL2 одной командой

Теория. В Windows 11 роль терминала играет PowerShell (или приложение "Терминал Windows"). Его нужно запустить от имени администратора - то есть с правом менять систему: кнопка "Пуск" → набрать "PowerShell" → правой кнопкой → "Запуск от имени администратора". После этого одна команда включает подсистему и ставит дистрибутив Linux по умолчанию - Ubuntu (самая распространённая версия Linux для начинающих). 

wsl --install

Что произойдёт: Windows включит нужные компоненты, скачает ядро Linux и попросит перезагрузить компьютер. После перезагрузки установка Ubuntu продолжится сама и один раз спросит имя пользователя и пароль для Linux - это отдельный от Windows аккаунт, только внутри WSL. Пароль при вводе не отображается вообще никак (даже звёздочками) - это нормально для Linux, просто печатай и нажимай Enter.

Пример. Проверочная команда wsl -l -v (сокращение от wsl --list --verbose) печатает список установленных дистрибутивов и, что важнее, столбец VERSION. Нам нужна цифра 2: если там 1, значит используется старая подсистема, в которой Docker работать нормально не будет. Звёздочка слева означает "дистрибутив по умолчанию".
PS>
Задание. Введи в тренажёре и нажми Enter: wsl -l -v
ПодсказкаКоманда пишется маленькими буквами, флаги через пробел: сначала -l (список), потом -v (подробно).
Показать разборВ выводе три столбца: имя дистрибутива (Ubuntu), состояние (Running - запущен, Stopped - остановлен, это не ошибка) и версия подсистемы. Нужна версия 2. Если стоит 1 - переключить можно командой wsl --set-version Ubuntu 2.

Docker Desktop с интеграцией WSL2

Теория. Docker - инструмент, который упаковывает программу вместе со всем, что ей нужно для работы (нужной версией языка, библиотеками, настройками), в один переносимый "ящик". Такой ящик одинаково запускается и на твоём ноутбуке, и на сервере. Именно в такие ящики мы дальше упакуем Демо Банк. На Windows ставится Docker Desktop - при установке нужно оставить включённой галочку про WSL2 backend / интеграцию с WSL, а после установки в настройках Docker Desktop (Settings → Resources → WSL integration) включить переключатель для своей Ubuntu. Без этого Docker будет виден в Windows, но не в линуксовом терминале, где мы работаем.

Разбор самого Docker - отдельная большая глава дальше. Здесь задача минимальная: поставить и убедиться, что он отвечает.

Пример. Проверка - команда docker --version, запущенная внутри Ubuntu (открыть "Пуск" → Ubuntu, или в Терминале Windows выбрать вкладку Ubuntu). Она печатает одну строку с версией. Если вместо этого появляется command not found - интеграция с WSL не включена, вернись в настройки Docker Desktop.
$
Задание. Введи в тренажёре: docker --version
ПодсказкаДва дефиса перед словом version, без пробела между ними.
Показать разборВывод в формате Docker version x.y.z, build <хеш>. Точные числа у тебя будут свои - важно только то, что команда вообще отвечает: значит, Docker установлен и виден из Linux-окружения.

git

Теория. git - система, которая хранит историю изменений файлов проекта: кто, что и когда поменял, и позволяет вернуться к любому прежнему состоянию. Это базовый инструмент, без которого дальше не будет ни одной главы. В Ubuntu внутри WSL он ставится через менеджер пакетов (программу-установщик самой системы) двумя командами: сначала обновить список доступных пакетов, потом поставить нужный. Существует и отдельный "Git for Windows" для PowerShell - в этой книге он не понадобится: весь проект живёт внутри WSL, и все команды дальше (включая git) мы даём именно из терминала Ubuntu, не из PowerShell. 

sudo apt update
sudo apt install git

sudo означает "выполнить с правами администратора" - система спросит тот пароль, который ты задал при установке Ubuntu. Разбор самого git, его логики и команд - следующая глава; здесь только установка и проверка.

Пример. Проверка - git --version. Формат вывода такой же короткий, как у Docker: слово, слово, номер версии.
$
Задание. Введи в тренажёре: git --version
ПодсказкаТот же приём проверки, что и с Docker - меняется только название программы.
Показать разборgit version x.y.z - обрати внимание, git печатает "version" без слова "git version ...," с запятой, как Docker. Формат вывода у каждой программы свой, единого стандарта тут нет.

VS Code и расширение WSL

Теория. Файлы проекта будут физически лежать внутри Linux-окружения, а не в обычных папках Windows - так быстрее и так же, как на сервере. Проблема: у Windows и Linux разные способы записывать путь к файлу (C:\Users\Ivan против /home/ivan), и обычный редактор в этих путях легко запутается. Решение - редактор VS Code плюс его официальное расширение WSL: редактор остаётся окном Windows, но работает с файлами напрямую внутри Linux, теми же путями, что и терминал.

Пример. Установил VS Code → в боковой панели Extensions нашёл расширение "WSL" → установил → открыл терминал Ubuntu, зашёл в папку проекта и набрал code . (точка = "текущая папка"). VS Code откроется, и в левом нижнем углу окна будет подпись вида WSL: Ubuntu - признак того, что редактор работает в Linux, а не в Windows.
Проверь себя. Почему держать файлы проекта внутри WSL и редактировать их через расширение WSL - лучше, чем хранить их в C:\Проекты и открывать оттуда?
ОтветПотому что дальше все команды (git, Docker) выполняются в Linux. Если файлы лежат в Windows-папке, Linux видит их через переходник: медленнее, и возможны странности с правами доступа и переносами строк. Внутри WSL всё ведёт себя так же, как на настоящем сервере.

Итог: что теперь стоит на машине

Теория. Четыре вещи, и каждая отвечает за свою роль: WSL2 - линуксовое окружение, похожее на сервер; Docker - упаковка программ в переносимые ящики; git - история изменений; VS Code с расширением WSL - редактор, который видит файлы внутри Linux. Этого набора хватает, чтобы в следующих главах начать собирать Демо Банк с нуля.
